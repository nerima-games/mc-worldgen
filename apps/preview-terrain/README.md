# apps/preview-terrain

mc-worldgen の**内蔵地形プレビュー**。plan.md §6 Step 2 の「本計画の最初の遊べる成果物」。

plan.md §2.3-4「プレビューは検証対象と同居する」に従い、
**このリポジトリの中の dev アプリケーション**である。
パッケージではない。`index.ts` からは公開されない。利用側から import できない。

```console
$ pnpm preview                  # 対話モード
$ pnpm preview --help           # キー割り当てとオプション
$ pnpm preview --stats          # 絵ではなく数値レポート
$ pnpm preview --once --ascii   # 1 フレームを文字で標準出力へ（issue に貼れる）
```

`pnpm verify` はこれを実行しない。ただし `pnpm typecheck`（`tsconfig.preview.json`）と
`pnpm lint` の対象には**入っている**。

## 3D ではなくターミナルに描いている理由

選択肢は「プレビューにだけ `three` を足す」だった。**却下した。**

1. **mc-worldgen の THREE 非依存は機構で保証されている。**
   `tsconfig.base.json` の `lib` に `"DOM"` が無いので、`new THREE.Vector3()` は
   このリポジトリのどこにも書けない（README「THREE.js を import しない」）。
   3D プレビューはどこかの tsconfig に `"DOM"` を戻すことを要求する。
   それは**機構的保証を、誰かが守る約束に格下げする**。
2. **バンドラとブラウザが要る。** `pnpm preview` はパイプできず、
   バグ報告に貼れず、地形を再現した当のマシンに ssh して動かすこともできなくなる。
3. **仕事として劣る。** [docs/testing.md](../../docs/testing.md) §3 が挙げる 6 点のうち
   「海面が本当に 63 か」「湖底に穴が空いていないか」の 2 つは、
   断面図なら一目で分かり、一人称視点では**掘らないと分からない**。

失うものも本物である。**山脈のシルエットは見えない**し、
洞窟の中に立つほうが断面を眺めるより説得力がある。
3D プレビューは mc-render ができたときにそちらに置くのが正しい
（参照実装の `packages/world` が THREE を 0 回しか import していないのと同じ線引き）。

## 3 つのビュー

| ビュー | キー | 何が見えるか | データ源 |
| --- | --- | --- | --- |
| `map` | `1` | 真上から。バイオーム色 + 起伏陰影 + 木 | 列クエリのみ（チャンク生成なし） |
| `height` | `2` | 表面高度。**海面ちょうどで色が切り替わる**。クランプ列は `!` / `_` | 列クエリのみ |
| `slice` | `3` | 垂直断面。**実際の `generateChunk` のブロック** | チャンク生成 |

`map` と `height` は `surfaceHeightAt` / `biomeFor` しか呼ばない。
`domain/terrain.ts` がこの 2 つを export している理由がそれで、
400×200 ブロックを描くのに 8 万回のノイズ評価で済む
（`generateChunk` 経由なら 313 チャンク = 20 MB のバッファを作って 8 万バイト読むことになる）。

`slice` はその近道を使えないし、使ってはいけない。
洞窟・水柱・植えられた木はブロックバッファの性質であって、列クエリは何も知らない。

**この分割自体が整合チェックになっている。** 同じ座標で `3` と `1` を往復すると、
`surfaceHeightAt` の予言と `generateChunk` の実物が一致しているかが目で分かる。

### 海面マーカーは目盛り側にある

`slice` ビューの左端は Y 目盛りで、10 ごとの数字に加えて**海面の行に `63>` が出る**。

フレームの中に線を引く実装を最初に書いたが、**一度も描画されなかった**。
`y == seaLevel` の行は、水没列なら WATER、そうでなければ固体であり、
**空気になるのは洞窟の中だけ**だからである。動いているように見えて死んでいる機能は、
無い機能より悪い。

```
     ..........::::,,,,,,,,,,,,,,,,,,:::..............................
 63> ~~~~~~::::::::,,,,,,,,,,,,,,,,,,::::::~~~~~~~~~~~~~~~~~~~~~~~~~~~
     ::::::::::::::,,,,,,,,,,,,,,,,,,::::::::~~~~~~~~~~~~~~~~~~~~~~~~~
```

（`--ascii --view slice --x 8 --z 144`。砂浜の島を挟んで両側の水面が `63>` の行で揃っている）

## docs/testing.md §3 の 6 点をどう見るか

| # | 確認事項 | やり方 |
| --- | --- | --- |
| 1 | シードを入れて地形を生成し飛び回れる | `--seed`、`wasd` / `q` `e` / `-` `=`、`[` `]` でシード送り |
| 2 | バイオームが色分けできる | `1`（map）。HUD にバイオーム構成比 |
| 3 | **海面が 63 だと目で分かる** | `3`（slice）。左の目盛りの `63>` の行と水面が一致する |
| 4 | **湖底に穴が空いていない** | `3` で水域の下を見る。`g` でガードを切ると穴が空く |
| 5 | 木が板になっていない | `1` で `T` の散らばり方。`--stats` の樹冠計測 |
| 6 | チャンク境界に継ぎ目が無い | `b` でチャンク格子。`--stats` の seam 計測 |

### 4 を実際に見るための座標

デフォルトシード `20260726` の**原点付近では洞窟が水域の床に届かない**ので、
`g` を押しても何も起きない。ガードが効いていないのではなく、出番が無い。

出番のある場所:

```console
$ pnpm preview --view slice --x 64 --z 144          # デフォルトシード
$ pnpm preview --seed 4242 --view slice --x -100 --z 60
```

`--seed 4242` は `test/carver.test.ts` が使っているシードである。
`--x -256 --z -256 --chunk-span 32` で `--stats` を取ると、
ガード ON で違反 0、`--no-guard` で **12,856 列**が壊れる。
ガードは飾りではない。

## ポータル枠を見る（`p` / `k` / `--portal`）

mc-kernel の `portal-frame.ts` の `detectNetherPortal` は、プレイヤーが置いた通常の
ポータル枠を検出するルールであり、その通常枠を地形生成する機能ではない。
このリポジトリには ruined portal の生成器はあるが、通常のポータル枠とは別の構造物なので、
どのシードのどの座標を飛んでも通常枠の portal は地形から出てこない。
そこで `p` は**オーバーレイ**を置く。地形そのものは 1 バイトも書き換えない。

```console
$ pnpm preview --once --ascii --portal --width 44 --height 22
```

`O` が黒曜石のリング、その内側の空白が点火すればポータルブロックになるセル、
`|` はカメラ列の十字線である。リングは地表ブロックの上に立つ。
HUD の `portal` 行が `detectNetherPortal` の判定をそのまま出す:

```
portal  4x5 x-axis, 20 portal cells at (0, 67, 0)
```

**`k` を押すこと。** リングの下辺（角ではない）から 1 ブロック抜けて、
判定が `NO FRAME` に変わる。変わらなければ検出器が穴の空いた枠を通している。
docs/testing.md §4-b F-4 は、このリポジトリが**落ちようのないガード**を
出荷した記録である。`k` はその視覚版であって、飾りではない。

角を抜いても判定は変わらない——これは**バグではなく仕様**である
（mc-kernel の `portal-frame.ts` のリング検査は角を要求しない）。
`k` が角ではなく下辺の中央を抜くのはそのためである。

なお十字線は**オーバーレイ込みのアクセサ**を読んでいる。
最初の版は素の地形を読んでいて、リング下辺の中央——
つまり `k` が抜くまさにそのブロック——に `|` を上書きしていた。
`k` を押しても見た目が変わらないプレビューになるところだった。

## `--stats` は 2 種類の走査をする

連続性ノイズは周波数 1/180 で引かれている。**地形 1 個の差し渡しが 180 ブロック**である。
だから 384×384 の密な走査から「世界の何割が海か」を読むと、
それは世界ではなく**その丘 2 個**の記述になる。このレポートの初版は実際にそれを間違えた。

- `SURVEY` — 疎で広い（既定: 8192 ブロックを 16 ブロック飛ばし）。**分布は全部こちら**
- `LOCAL` — 密で狭い。**隣接が要るものだけ**（チャンク継ぎ目、木の間隔）
- `BLOCKS` — 実際に生成したチャンク（水面 Y、hollow-lake、洞窟率、樹冠の塊）

`--stats` は表示するだけで、何も assert しない。
ここで本物の不変条件だと分かったものは `test/` に移すべきである。そこなら CI を落とせる。

## 時計を読んでいない

アニメーションが無く、フレームはキー入力にだけ応答するので、
`Date.now()` / `new Date()` / `performance.now()` はこのアプリのどこにも無い。
`scripts/check-dependency-whitelist.ts` の
`mc-kernel-allow-time-source` エスケープハッチは**使っていない**。

`(seed, coord)` の純関数にはアニメーションさせるものが無い、というだけの話である。

## 依存

**このリポジトリ自身のモジュールだけ。** org パッケージも npm 依存も色ライブラリも無い。
`apps` は `SCAN_ROOTS` に入っているので、import は `domain/` と同じゲートを通る。
